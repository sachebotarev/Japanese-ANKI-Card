# AGENTS

Короткая инструкция для ИИ-агента, работающего в этом репозитории.

## Что делать

- Работать с проектом как с пайплайном `Слова/ -> Карточки/ -> Картинки/ -> Произношение/ -> Anki`; при **создании новой** карточки после готового JSON — ещё заметка в `Записи/` по [docs/zapisi-spec.md](docs/zapisi-spec.md).
- Использовать русский язык для переводов, пояснений и заметок.
- Считать `docs/` основным источником подробных правил.
- Перед массовыми изменениями или синхронизацией с Anki сверять актуальные поля заметки через инструменты Anki.

## Оперативные правила

- Перед обработкой файлов в `Слова/` нужно удалить пустые строки, убрать дубли и отсортировать строки.
- Одна карточка хранится в одном JSON-файле.
- Тема должна совпадать между `Слова/`, `Карточки/`, `Картинки/` и `Произношение/`.
- В поле `Пример` нужно записывать ровно 3 примера в одном текстовом поле, разделяя предложения тегом `<br>`: первый — простой начального уровня, второй — средней сложности с грамматикой не выше N5, третий — сложный комплексный с несколькими грамматическими конструкциями, но не выше N4.
- Поля `Пример без слова` и `Пример перевод` должны повторять ту же трёхпримерную структуру и порядок примеров, что и поле `Пример`, тоже через тег `<br>`.
- Для лексики, которая относится к учебнику **Minna no Nihongo** («みんなの日本語»), в поле `Теги` нужно добавлять тег с **номером урока（課）** соответствующего тома в формате из [docs/cards-spec.md](docs/cards-spec.md) (раздел «Теги»). Для слов вне программы этого учебника такой тег не ставят.
- Если пользователь дал слово без указания темы или файла, тему нужно определить самостоятельно. Сначала сверься с таксономией в [docs/theme-taxonomy.md](docs/theme-taxonomy.md), затем сопоставь с папкой в `Слова/` по [docs/theme-repo-bridge.md](docs/theme-repo-bridge.md). Сначала выбирай наиболее подходящую уже существующую папку, новую создавай только если разумно обойтись без неё нельзя (см. [docs/word-lists.md](docs/word-lists.md)).
- Каталоги **Глаголы**, **Наречия**, **Прилагательные_い**, **Прилагательные_な** по этой таксономии **не переклассифицируют** и не сливают с смысловыми темами: глаголы и наречия остаются в своих разделах, прилагательные — в своих.
- Если добавляется существительное (или иная лексика вне глаголов/наречий/прилагательных_い/_な), её нужно классифицировать по теме применения по таксономии и мосту к папкам, а не по части речи как таковой. Примеры имён папок: **Образование**, **Торговля**, **Еда**, **Жилище**, **Одежда**, **Медицина**, **Эмоции**, **Дружба**, **Право**, **Туризм**, **Кинематограф**, **Телевидение**, **Фотография**, **Электроника** и другие из `Слова/`.
- Отдельной темы `Существительные` в проекте нет: существительное нужно отнести к конкретной теме применения или завести новую тему по правилам ниже.
- Если для существительного действительно нужна новая тема, её можно создать только когда слово и ожидаемые соседние слова образуют осмысленную устойчивую группу, а существующие темы подходят заметно хуже.
- Не нужно плодить новые темы ради одного частного существительного, если его можно без натяжки отнести к уже существующей теме.
- Если пользователь дал слово без указания темы или файла, агент обязан не только выбрать тему, но и фактически отнести слово в соответствующий файл `Слова/<тема>` и в соответствующую папку `Карточки/<тема>/`, если для выбранного файла нет отдельного явного запрета.
- Нельзя считать это правило выполненным, если агент создал только JSON-карточку, но не обновил соответствующий файл в `Слова/`, когда обновление этого файла разрешено.
- Если в JSON поле `Картинка` хранит текстовый промпт и есть техническая возможность генерации, картинку нужно создавать сразу, без дополнительных вопросов пользователю, сохранить в `Картинки/<тема>/`, затем заполнить ей поле `Картинка` в Anki. Картинка всегда должна опираться на смысл третьего примера.
- Картинка должна не просто соответствовать примеру, а явно акцентировать внимание на изучаемом слове и его роли в сцене.
- Для генерации иллюстраций карточек нужно использовать нормальную raster AI-генерацию, а не самодельные плейсхолдеры, примитивные программные рисунки, SVG-заглушки или схематичные иконки вместо полноценной сцены.
- **Размер и пропорции:** предпочтительно 512×512 (1:1). **Никогда не искажать** изображение ради квадрата: если исходник не квадратный — сохранять как есть; не применять принудительный `resize` с разными масштабами по ширине и высоте. Подробнее — [docs/cards-spec.md](docs/cards-spec.md) (раздел «Правила для картинки»).
- Промпты для anime-сцен — по [docs/prompt-generation-rule.md](docs/prompt-generation-rule.md): короткие визуальные блоки, явное число людей, физический ключевой объект, запрет текста и букв на изображении.
- Если доступен встроенный инструмент генерации изображений, для карточек его нужно считать основным способом создания иллюстраций; при вызове указывать квадратный кадр (`aspect_ratio` 1:1).
- Если карточки нет в Anki, её нужно создать из JSON.
- При создании **новой** карточки (новый JSON в `Карточки/<тема>/`) нужно добавить заметку `Записи/<тема>/<Слово>.md` по правилам [docs/zapisi-spec.md](docs/zapisi-spec.md), когда JSON и связанные файлы позволяют собрать заметку без искажений. Если создать заметку **не удаётся** (нет обязательных полей, не три примера по `<br>`, нет файла картинки в `Картинки/<тема>/`, нет одного или нескольких из четырёх mp3 в `Произношение/<тема>/`, иная блокирующая причина) — **не создавать** файл заметки и **не оставлять** пустую или обрезанную заглушку; в ответе пользователю **явно указать причину**, по которой шаг `Записи/` пропущен.
- Если карточка уже есть, обновлять её нужно по правилам из `docs/anki-sync.md`.
- После создания новой карточки и связанных с ней файлов агент должен сделать git-коммит и залить изменения в удалённый репозиторий, если пользователь явно не запретил это отдельным указанием.
- Если в JSON поле `Произношение` пустое, озвучку нужно делать по правилам из `docs/audio.md`. Если примеры в Anki не совпадают с примерами в JSON, поле `Произношение` в Anki нужно перезаписать по актуальному JSON. Озвучиваются слово и все три примера, поэтому для новой карточки должно получаться 4 отдельных аудиофайла.
- Для озвучки через `AivisSpeech` разрешены только голоса из белого списка в [docs/audio.md](docs/audio.md); скрипт `generate_aivis_audio.py` задаёт их явно. Случайный выбор — **отдельно для каждой озвучиваемой фразы** (слово и каждый из трёх примеров), а не один раз на запуск скрипта или на всю карточку (см. `docs/audio.md`).
- Для озвучки через `AivisSpeech` по умолчанию нужно использовать скорость `90%`.
- Если пользователь пишет короткий запрос вроде `Добавь слово 口座` или `Создай карточку для слова 口座`, это нужно трактовать как запрос на полный пайплайн, если пользователь явно не ограничил объём работы.
- Для короткого запроса полный пайплайн по умолчанию включает и обновление `Слова/<тема>`, если для выбранной темы это не запрещено отдельным правилом.
