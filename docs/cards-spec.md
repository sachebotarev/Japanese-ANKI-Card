# Спецификация карточек

## Общие принципы

- Все переводы, пояснения и заметки в карточках должны быть на русском языке.
- Основная колода Anki: `Японские слова`.
- Основной тип заметки Anki: `Японские слова`.
- Перед созданием или массовым обновлением карточек нужно сверять актуальные поля заметки через доступные инструменты Anki.
- Одна карточка хранится в одном JSON-файле.
- Разные чтения одного написания хранятся отдельно: дополнительный файл имеет имя `<Слово>（<чтение>）.json`; поле `Слово` сохраняет само японское слово, а поле `Чтение` содержит только чтение этой карточки. Картинка, четыре MP3 и Markdown используют тот же базовый файл с уточнением чтения, чтобы медиа не перезаписывались.

## Учебная точность и различение близких слов

Карточки — учебный материал, по которому ученик формирует понимание слова. Приоритет — максимально корректно и ясно передать значение и естественное употребление, не закрепляя ошибочные ассоциации, путаницу и необходимость последующего переучивания.

- Передавать в русском переводе изучаемое значение и его границы; не объединять близкие слова одним расплывчатым набором переводов, если это стирает существенное различие.
- Выбирать естественные, типичные сочетания: уже первый простой пример должен ясно показывать основное изучаемое значение. Не делать пограничное, редкое или требующее особого контекста употребление опорным примером.
- Для легко смешиваемых слов подбирать различающие контексты и явно пояснять отличие в поле `Заметки`: например, `割る` — разбить или расколоть предмет на части (`コップを割る`), `壊す` — нарушить устройство, конструкцию или работу вещи (`時計を壊す`). Не использовать стакан или вазу как основные учебные примеры для `壊す`, когда цель — отличить его от `割る`.
- Не превращать учебное различие в ложный абсолютный запрет: если значения пересекаются, пояснять, что речь о смысловом фокусе и типичных сочетаниях, а не о невозможности другого употребления.
- Согласовывать перевод, японские примеры, управление, спряжение, чтение, иллюстрацию и аудио; не смешивать самостоятельный непереходный глагол, страдательную и потенциальную формы.
- После изменения примеров обновлять связанные картинку, аудио, Anki и Markdown по правилам синхронизации, чтобы ученик нигде не получил прежний ошибочный контекст.

## Обязательные поля JSON

- **Слово** — словарная форма, по возможности в кандзи.
- **Перевод** — общепринятый русский перевод, предпочтительно по авторитетному словарю.
- **Чтение** — хирагана или катакана.
- **Подсказка** — мнемоника без прямого раскрытия целевого слова и без однокоренных подсказок.
- **Пример** — одно текстовое поле с ровно тремя японскими предложениями, разделёнными тегом `<br>`. Во всех трёх примерах изучаемое слово нужно оборачивать в `<span class='study-word'>...</span>`. Примеры идут в фиксированном порядке: первый — простое предложение начального уровня, второй — предложение средней сложности с грамматикой не выше N5, третий — сложное комплексное предложение с несколькими грамматическими конструкциями, но не выше N4.
- **Пример без слова** — те же три предложения в одном поле через тег `<br>`, где целевое слово в каждом примере заменено на `_____`. Порядок примеров должен строго совпадать с полем **Пример**.
- **Пример перевод** — три русских перевода в одном поле через тег `<br>`, по одному переводу на каждый пример поля **Пример** и в том же порядке.
- **Картинка** — на этапе подготовки карточки это текстовый промпт для генерации изображения 512×512 по смыслу третьего примера из поля **Пример перевод**. После загрузки изображения в Anki это поле может быть синхронизировано обратно как HTML или ссылка на уже используемую картинку.
- **Произношение** — при первичном создании карточки не заполняется. После генерации аудио обычно содержит 4 ссылки: `[sound:...][sound:...][sound:...][sound:...]` для слова и трёх примеров.
- **Заметки** — важные для изучения сведения об употреблении слова по правилам раздела «Содержание поля Заметки». Краткость не должна приводить к пропуску управления, спряжения или существенных ограничений; прежний лимит в два предложения не применяется.
- **Кандзи-разбор** — разбор кандзи в слове.
- **Показать фуригану** — `N`, если слово состоит только из каны/катаканы и кандзи из первого тома **Basic Kanji Book**; `Y`, если в слове есть хотя бы один кандзи вне первого тома **Basic Kanji Book**.
- **Теги** — массив строк с тегами проекта. Используются как теги заметки в Anki и **дословно** копируются в YAML ключ **`tags`** заметки в `Записи/` при сборке по [zapisi-spec.md](zapisi-spec.md). На сайте Quartz те же строки становятся **кликабельными тегами** над текстом страницы и попадают в индекс **`/tags/`**, так что по тегу урока Minna (формат см. ниже в разделе «Теги») можно отобрать все карточки этого урока.

## Содержание поля Заметки

Техническое имя поля в JSON и Anki — **`Заметки`**. Пользовательское название «Заметка» означает это же поле, а не отдельное поле и не весь Markdown-файл в `Записи/`.

Заметка должна помогать правильно употреблять именно изучаемое значение слова. Писать по-русски, приводя короткие японские сочетания с переводом или пояснением роли частиц. Не заполнять поле повтором перевода, одним названием части речи, общими фразами вроде «часто используется в речи», мнемоникой, разбором кандзи или техническими сведениями о карточке. Не добавлять редкие значения ради полноты словаря.

### Глаголы и глагольные выражения

- Структура поля: **Спряжение → Переходность → Пара (если есть) → Частицы → Особенности**. Каждый блок — с отдельной строки через `<br>`, название блока выделяется `<b>…:</b>`. В «Частицах» указывать модели и роли участников; в «Особенностях» — существенные отличия конкретного слова. Не дописывать повторную классификацию в конце: при исправлении согласовать всю заметку. Для разных чтений одного написания проверять заметки отдельно. Отсутствие пары не заполнять шаблонной фразой.
- Указывать переходность: **переходный (他動詞)**, **непереходный (自動詞)** либо **переходное и непереходное употребление (自他動詞; лабильный в широком учебном смысле)**. Для последнего случая приводить обе модели и объяснять разницу значений. Не называть глагол лабильным только из-за опущенного дополнения; を при пути или месте выхода само по себе не означает переходности. Если карточка изучает лишь одно употребление, явно выделять его.
- Давать частые модели управления с ролью каждой частицы: например, `人に会う` — встретиться с человеком; `場所で人に会う` — место встречи с で. Не приводить набор частиц без объяснения, к каким участникам ситуации они относятся.
- Указывать **спряжение**: I группа / 五段, II группа / 一段 или III группа / неправильный глагол. Для выражения указывать изменяемый глагол. Давать опорные формы **〜ます, 〜ない, 〜て**, отмечать исключения и нестандартные формы; полную таблицу форм не требуется переносить в заметку.
- Объяснять важные особенности: типичные сочетания, ограничения, регистр, значение 〜ている, отличие от близкого слова или парного глагола — когда это существенно для данного слова. Парный глагол приводить с коротким различием моделей, если он помогает обучению; шаблонное «устойчивой пары нет» без учебной пользы не добавлять.
- Не смешивать лексическую переходность, страдательные, потенциальные и каузативные формы. Для производной формы или служебной конструкции объяснять её образование и употребление, не выдавая за самостоятельный парный глагол.

### Существительные

Объяснять существенные особенности употребления: типичные сочетания и конструкции, нужные частицы, счётное слово, возможность употребления с する, регистр, границы значения и отличие от близких слов — только то, что относится к конкретному слову и помогает избежать ошибки. Не приписывать каждому существительному обязательную частицу, счётное слово или сочетаемость с する.

### Прилагательные

Указывать тип (い / な, а при необходимости особую конструкцию) и важные особенности употребления: связь с существительным, наречная форма, управление, ограничения, нерегулярные формы и отличие от близких слов. Например, для 好き существенны `Nが好き`, `好きなN`, `Vることが好き`; одного перевода «нравится» недостаточно.

### Наречия

Объяснять особенности значения и **обычное место в предложении**: что наречие уточняет и где обычно стоит относительно этого компонента. Указывать, если позиция меняет смысловой охват; не выдавать обычную позицию за единственно допустимую. Приводить важные сочетания с отрицанием, временем, видом или определённой конструкцией, если они требуются слову; отмечать употребление с と / に, если оно характерно.

### Остальные слова и конструкции

Объяснять их функцию и особенности употребления: к чему присоединяются, где стоят, какие формы требуют, в какой ситуации и регистре уместны, чем отличаются от легко смешиваемых выражений. Не подменять объяснение названием части речи.

### Проверка и обновление

- Проверять заметку по чтению, переводу и примерам конкретной карточки. Не выводить спряжение только по окончанию 〜る, переходность — по русскому переводу, а управление — по одному примеру. При сомнении сверяться со словарём или грамматическим источником.
- Сохранять уже имеющиеся полезные сведения, удаляя ошибки, повторы и пустые формулировки. Разделять смысловые блоки через `<br>`; не использовать Markdown-разметку внутри поля Anki.
- При исправлении только заметок обновлять поле `Заметки` в JSON, соответствующий раздел существующего Markdown и это же поле в Anki. Соблюдать приоритет исправлений с красным флагом по [anki-sync.md](anki-sync.md); перед массовой записью проверять актуальные поля Anki. Проверять совпадение заметок после записи.

## Теги

- Поле `Теги` в JSON должно содержать все теги, которые нужно применить к заметке в Anki.
- Внутри одного тега пробелы заменяются на `_`: `Вопросительные_слова`, `Счётные_суффиксы`. Anki разделяет теги пробелами; одинаковое написание сохраняется в JSON и YAML Markdown.
- Для глаголов нужно добавлять тег `動詞`.
- Для существительных нужно добавлять тег `名詞`.
- Для слова нужно добавлять тег уровня JLPT: `N5`, `N4`, `N3`, `N2` или `N1`.
- Для глаголов нужно добавлять тег со спряжением.
- Для карточки нужно добавлять тег, совпадающий с поддиректорией в `Карточки/`, где лежит JSON-файл.
- Служебные метки происхождения импорта или инструмента не добавляют в `Теги`: они не являются учебными категориями. Не дублируют также название темы другим написанием и часть речи переводом уже имеющегося тега.
- **Учебник «みんなの日本語» (Minna no Nihongo):** если изучаемое слово **относится к лексике** этого учебника (том 初級 I или 初級 II), в `Теги` обязательно добавляют **один** тег с **номером урока（第…課）** в оглавлении **того тома**, где это слово вводится как учебная единица (в терминах учебника это соответствует «главе» в смысле раздела для прохождения — **урок**, а не отдельная книжная 章). Формат строки тега:
  - `みんな初級I-第NN課` — урок `NN` тома 初級 I (`NN` с ведущим нулём: `01` … `25`, как в оглавлении тома);
  - `みんな初級II-第NN課` — урок `NN` тома 初級 II, аналогично.
  При необходимости рядом можно оставлять общий тег `みんなの日本語` (если он уже используется в колоде). Если слово **не входит** в программу Minna (только расширенная лексика, другой источник и т.д.), тег урока **не добавляют**. Если в учебнике формально затронуто несколько уроков, берут **урок первичного введения**; второй тег того же формата — только при явной педагогической необходимости.

## Правила для картинки

- Картинка создаётся по смыслу третьего примера из поля **Пример перевод** и должна акцентировать внимание на изучаемом слове.
- Изучаемое слово должно быть визуальным центром сцены: главный объект, главное действие или самый заметный смысловой фокус иллюстрации.
- Для стабильных anime-промптов (короткие визуальные блоки, число людей, физический ключевой объект, запрет текста/букв) используйте [prompt-generation-rule.md](prompt-generation-rule.md).
- **Предпочтительный размер** — 512×512 px (квадрат 1:1). При генерации нужно запрашивать квадратный кадр.
- **Запрещено искажать пропорции:** нельзя растягивать или сжимать изображение до квадрата, если исходник не квадратный. Недопустимы операции вроде `resize((512, 512))` для 1536×1024 и любые другие преобразования, меняющие соотношение сторон.
- Если генератор выдал не квадрат (например 1024×1024, 1536×1024) — **сохранять и использовать файл как есть** в `Картинки/<тема>/`. Допустимо только **пропорциональное** уменьшение (одинаковый масштаб по обеим осям), если нужен меньший файл; менять aspect ratio нельзя.
- Если квадрат 512×512 получить нельзя — не «дожимать» картинку; лучше оставить нативное разрешение без деформации, чем испортить качество.
- Финальная картинка должна быть полноценной raster AI-иллюстрацией или другой качественной готовой иллюстрацией по смыслу карточки, а не примитивной программной заглушкой.
- Локальный файл сохраняется в `Картинки/<тема>/` с тем же базовым именем, что и JSON-карточка: `<Слово>.jpg` или `<Слово>.png`.
- Папка `<тема>` должна совпадать с темой исходного списка в `Слова/` и JSON-файла в `Карточки/`.
- Пока изображение ещё не сгенерировано, поле **Картинка** в JSON считается источником промпта.
- Если есть техническая возможность создать изображение, картинку нужно сгенерировать по этому промпту сразу, без дополнительных вопросов пользователю, сохранить локально в `Картинки/<тема>/` и использовать этот файл для заполнения поля **Картинка** в Anki.
- После загрузки изображения в Anki поле **Картинка** в самой заметке Anki должно содержать картинку, например через HTML или ссылку на импортированный файл.
- После обратной синхронизации JSON поле **Картинка** может быть заменено на HTML или ссылку из Anki. Это нормально для уже обработанной карточки.
- Если изображение нужно сгенерировать заново, сначала в JSON поле **Картинка** нужно снова записать новый текстовый промпт по смыслу третьего примера, а уже потом повторять цикл генерации и синхронизации.
