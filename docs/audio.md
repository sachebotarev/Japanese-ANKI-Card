# Озвучка

Правила первичной генерации применяются к карточкам, у которых в JSON поле **Произношение** пустое. Исправление по `Flag 2` описано отдельно ниже и возможно при уже заполненном поле.

## Общие правила

- Озвучка генерируется локально через `AivisSpeech`.
- Для генерации используется скрипт `scripts/generate_aivis_audio.py`.
- Разрешены **только** следующие голоса (полное имя `speaker` как в ответе `GET /speakers` локального Engine; список дублируется в коде скрипта):
  - `かりん(現実20代女子AIボイチェン@リアボVC公式モデル)`
  - `阿井田 茂`
  - `にせ`
  - `わかな(現実20代女子AIボイチェン@リアボVC公式モデル)`
  Другие голоса для карточек проекта использовать нельзя. Перед добавлением правила они были проверены на наличие в установленном `AivisSpeech` (все четыре присутствовали со стилем `ノーマル`).
- Если флаг `--speaker` **не** передан: перед **каждым** из четырёх MP3 (слово и три примера) скрипт **заново** случайно выбирает один из **установленных** разрешённых голосов, поддерживающих выбранный стиль. Один случайный выбор «на весь запуск» или «на всю карточку» не допускается.
- Если передан `--speaker`, должен использоваться один из голосов из списка выше — для всех четырёх файлов этой генерации сохраняется этот голос.
- По умолчанию стиль — `ノーマル` (можно переопределить через `--style`, только если голос поддерживает этот стиль).
- По умолчанию скорость озвучки в `AivisSpeech` должна быть `90%` (`speedScale = 0.9`).
- Перед указанием нестандартного стиля имеет смысл свериться с ответом `GET /speakers` для выбранного голоса.

## Что нужно создать

Для каждой карточки должны существовать ровно четыре MP3-файла:

- `<Слово>_слово.mp3`
- `<Слово>_пример_1.mp3`
- `<Слово>_пример_2.mp3`
- `<Слово>_пример_3.mp3`

Все четыре файла сохраняются в `Произношение/<тема>/`, сохраняя структуру проекта.

## Что озвучивается

- отдельный файл для значения поля **Чтение**; имя файла по-прежнему берётся из поля **Слово**;
- отдельный файл для первого примера из поля **Пример** без HTML-разметки;
- отдельный файл для второго примера из поля **Пример** без HTML-разметки;
- отдельный файл для третьего примера из поля **Пример** без HTML-разметки.

При массовой генерации примеры передаются движку в исходной японской записи с кандзи и контекстом. Поля **Пример**, **Пример без слова** и **Пример перевод** ради озвучки не меняются.

## Исправление произношения по Flag 2

- Оранжевый флаг Anki `flag:2` означает, что пользователь заметил неверное произношение при изучении карточки. Это отдельный сигнал от красного `flag:1`, который относится к исправленным данным карточки.
- По запросу на обработку таких карточек найти карточки с `flag:2` и определить ошибочный файл: слово или один/несколько из трёх примеров. Если по доступным сведениям нельзя выделить конкретный пример, проверить и при необходимости пересоздать все три; слово озвучивать по полю **Чтение**.
- Для исправления примера агент делает **отдельный запрос к LLM**: передаёт исходное японское предложение и поле **Чтение** целевого слова, просит переписать всё предложение полностью на хирагане, сохранив смысл, грамматическую форму и пунктуацию без перевода или пересказа. Это текст только для синтеза, а не новое значение поля **Пример**.
- Перед синтезом агент проверяет результат: нет кандзи, катаканы, латиницы и цифр; чтение изучаемого слова соответствует контексту и форме; остальная часть предложения не изменена по смыслу. Ответ LLM сам по себе не считается достаточной проверкой.
- Перегенерировать только затронутые MP3, загрузить их в медиа Anki под теми же именами (при необходимости заменить существующие файлы), убедиться, что карта воспроизводит исправленное аудио, и лишь затем снять `flag:2`. Ссылки `[sound:…]` в JSON и Anki обычно не меняются; исходные японские примеры и переводы остаются прежними.
- Отдельное слово с ошибкой пересоздаётся из поля **Чтение** без LLM-транскрипции. Для существующих файлов это действие выполняется только при выявленной ошибке; массовая перегенерация не требуется.

Для отдельного слова:

```bash
python3 scripts/generate_aivis_audio.py --repair-word \
  'Карточки/<тема>/<Слово>.json'
```

Для одного примера после проверки транскрипции:

```bash
python3 scripts/generate_aivis_audio.py --repair-example 2 \
  --hiragana-text 'きょうはともだちとえきへいきました。' \
  'Карточки/<тема>/<Слово>.json'
```

Каждая команда перезаписывает только указанный MP3 локально и не изменяет JSON. Загрузка нового MP3 в Anki и снятие флага выполняются после проверки.

## Обновление JSON и Anki

- Поле **Произношение** в JSON обновляется через `--write-json` или вручную в формате `[sound:<Слово>_слово.mp3][sound:<Слово>_пример_1.mp3][sound:<Слово>_пример_2.mp3][sound:<Слово>_пример_3.mp3]`.
- Если поле **Произношение** в Anki ещё пустое, в него нужно добавить ссылки на созданные аудиофайлы.
- Если поле **Произношение** в Anki уже заполнено, его не нужно перезаписывать только потому, что в JSON оно ещё пустое.

## Базовый запуск

```bash
python3 scripts/generate_aivis_audio.py --write-json 'Карточки/Глаголы/乾かす.json'
python3 scripts/generate_aivis_audio.py --all-empty --write-json
```

## Поведение скрипта

- использует локальный `AivisSpeech Engine` на `http://127.0.0.1:10101`;
- если engine не запущен, пытается стартовать его из установленного `AivisSpeech.app`;
- для файла `<Слово>_слово.mp3` озвучивает значение поля **Чтение**, сохраняя исходное имя файла;
- ограничивается белым списком голосов в коде скрипта;
- если `--speaker` не передан — новый случайный выбор из этого списка **на каждый** из файлов `_слово.mp3`, `_пример_1.mp3`, `_пример_2.mp3`, `_пример_3.mp3` (пропуск существующих файлов без `--force` не перегенерирует и не меняет голос до следующей записи этого файла);
- по умолчанию выставляет `speedScale = 0.9`;
- ожидает, что в поле `Пример` лежат ровно 3 непустых примера нового формата, разделённых тегом `<br>`;
- сохраняет аудио в `Произношение/<тема>/`;
- обновляет поле `Произношение` в JSON только при флаге `--write-json`.
